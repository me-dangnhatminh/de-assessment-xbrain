| Generated evidence → report/manifest | Tampered or stale artifacts could be presented as verified customer results. |
| CLI `--clean`/output root → filesystem | Destructive cleanup must remain limited to known generated Phase 1 files. |
| Documentation/Make commands → reviewer shell | Commands must be exact, locked, and free of secret/network/cloud assumptions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-SC | Tampering | Locked dependency execution | high | mitigate | Canonical targets run `uv lock --check` and `uv sync --locked` against the human-approved Plan 01 lock. |
| T-01-15 | Tampering | `run_manifest.json` / committed evidence | high | mitigate | Hash every required artifact and SQL file, bind row counts/query IDs/paths, and fail verification on any mismatch. |
| T-01-16 | Elevation of Privilege | `--clean` path handling | high | mitigate | Resolve the root, reject supplied/project roots, enumerate exact generated targets, and test refusal before deletion. |
| T-01-17 | Repudiation | reviewer report claims | medium | mitigate | Render answers only from result files and cite SQL, dataset hash, counts, and manifest ID beside each claim. |
| T-01-18 | Information Disclosure | README/manifest | low | accept | Phase 1 has no credentials/account identifiers; manifest allowlists non-secret runtime versions and local paths relative to the repository. |
| T-01-19 | Denial of Service | full verification | low | accept | Work is a bounded local 2,923-line dataset with four fixed queries; command failure remains visible and restartable through atomic outputs. |
