## Trust Boundaries

| Boundary | Description |
|---|---|
| Untrusted JSONL bytes → parser/validator | Malformed, oversized, structurally invalid, duplicated, or misleading records enter deterministic code. |
| Validated record → analytical Parquet | Rejected data must not cross this quality boundary; raw provenance must remain attributable. |
| CLI paths → generated writers | Input/output aliasing could mutate sources or unrelated files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-SC | Tampering | Locked Python dependencies | high | mitigate | Consume only the human-approved Plan 01 `uv.lock`; no new package-manager install surface is introduced in this plan. |
| T-01-05 | Tampering | output path validation and writers | high | mitigate | Resolve paths, reject all outputs within `docs/onboard`, hash supplied files before/after, and atomically replace only explicit generated paths. |
| T-01-06 | Denial of Service | `iter_source_lines` / JSON parsing | medium | mitigate | Stream one line at a time and reject lines above the documented 1 MiB maximum before parsing. |
| T-01-07 | Repudiation | validation/disposition | medium | mitigate | One ledger record per physical line retains raw line, all issue reasons/actions, normalization values, final action, source hash, and duplicate cross-reference. |
| T-01-08 | Information Disclosure | diagnostics and ledger | low | accept | The supplied records are fictional and the full ledger is a required reviewer artifact; normal CLI logging omits bulk raw-record dumps. |
| T-01-09 | Spoofing | provenance fields | medium | mitigate | Source-line identifiers are bound to the byte-level source SHA-256 and canonical record digest rather than caller-provided record fields. |
</threat_model>
